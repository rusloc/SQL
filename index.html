Purchase-order tracking view: PO lines matched to shipments, lead times and SLA exceptions, customs, invoices. One row per PO line per shipment, with the remaining quantity as its own line until it reaches zero.

More scripts land here as they are anonymized. Each gets a folder with the script, a NOTES.md on what changed and why, and the before and after numbers.

The deploy pattern

Each file is self-contained: the query goes into a session variable with dollar quoting, then into a sql_source table keyed by report and page. The semantic model reads one row. Editing the file changes nothing on its own: edit, run, refresh, commit.

set dev.po_view =
$sql$
    ...the query...
$sql$;

update sql_source
set  _code    = current_setting ( 'dev.po_view' )
    ,_updated = now()
where 1=1
    and _report = 'TRACKER'
    and _page   = 'PO VIEW';

The biggest single win was not the big tables. Two per-row lookups on a small port table took 73 percent of the old run time and moved hundreds of gigabytes through the buffer cache. The planner expected 14 trillion rows at one window step; 1,600 came out.

House style

  • Keywords lowercase. One column per line, leading commas.
  • Every output column gets a _ alias, no as, right-aligned into one block.
  • One-letter table aliases. where 1=1, then one and per line, so any filter can be toggled.
  • case / when / then stepped one indent per level.

What anonymized means here

  • Company, system, client and report identifiers renamed consistently across table names, column names, literals and comments.
  • Site names, airport and partner codes, debug serials replaced with placeholders.
  • Nothing else changed. None of the scripts will run outside its source database, and that is the point.
